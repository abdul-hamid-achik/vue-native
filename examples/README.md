# Examples

Seventeen runnable apps, ordered from "first component" to "desktop app". Each
row lists what the app actually teaches and the components/composables its
`.vue` sources really use — generated by grepping the sources, not copied from
the per-app READMEs.

Every example is **Vue source plus build config only** unless the "Native host"
column says otherwise. See [Running an example](#running-an-example).

## Running an example

All examples build the JS bundle the same way:

```bash
cd examples/counter
bun install          # from the repo root on a fresh clone
bun run build        # emits dist/vue-native-bundle.js
```

Getting that bundle onto a screen needs a **native host** — an Xcode or Gradle
project that embeds `VueNativeCore` and loads the bundle. Only `calculator`,
`counter`, `settings` and `todo` ship one (iOS only), and no example ships an
Android or macOS host.

For every other example:

```bash
bunx vue-native create my-app     # scaffolds iOS + Android hosts
```

then copy `app/`, `vite.config.ts` and `env.d.ts` from the example over the
scaffold's equivalents, rebuild, and open the generated project in Xcode or
Android Studio. `vue-native create` does not scaffold a macOS shell yet, so
`macos-showcase` needs an existing macOS Xcode project.

Each example's own README repeats this at the top.

## Typechecking

Every example runs `vue-tsc --noEmit`, which type-checks `.vue` templates as
well as `.ts`. Plain `tsc` silently skips `.vue` files — which is how the broken
call sites these examples used to contain went unnoticed. Run one with:

```bash
cd examples/lists && bun run typecheck
```

or all of them from the repo root with `bun run typecheck`.
